# Moirasia — domain vocabulary

Moirasia is a macOS controller and feature host. This file is the short glossary; `docs/architecture/standalone-applications.md` is the full architecture document and wins on detail.

## Terms

- **Application identity** — separate local- and native-mode implementations: `apps/integrated/Bonded/src/main/application-identity.ts` and `native/moirasia-runtime/Sources/BondedRuntime/ApplicationIdentity.swift`. Both use `bundle:<id>|path:<path>` for a non-empty bundle identifier and `path:<path>` otherwise. Matching compares exact key representations, ignores `targetKind`, and does not match a one-sided bundle identifier; the existing unescaped `|path:` format can still collide for distinct bundled path/identifier pairs. Swift compares UTF-8 `Data` to preserve TypeScript string-equality behavior; paths and identifiers remain case- and normalization-sensitive. The local resolver supplies the containing `.app` path; native resolution supplies the raw `proc_pidpath` executable path. IDs and state are mode-local: TypeScript stored-rule IDs use `app_`, native observed IDs use `app_`, and native stored-rule IDs use `rule_`.
- **Enforcement** — `apps/integrated/Bonded/src/main/enforcement.ts`; owns the blocking-state transitions: the startup reconciliation, applying selections to the PF firewall, failing open when the helper is unavailable, and rolling back settings, firewall configuration, and learned addresses on failure. The controller decides when transitions happen; Enforcement owns how they land.
- **Controller** — `src/main/application-controller.ts`; the Moirasia main-process side that discovers, opens, focuses, and quits Amove, Bonded, and Shout through the AppKit agent and the `--moirasia-control` protocol. It owns the applications fact — agent records merged with catalog facts, login-item results, and per-application error capture — and serializes per application, so concurrent open, quit, explicit login-item changes, and pending login-item retries on one application land in order. It composes the ControllerSnapshot from the applications fact, the `AppearanceRegistry`, and the Feature runtime; the renderer's initial state is the shared `emptyControllerSnapshot()` default.
- **Host ownership** — `src/main/host-ownership.ts`; the Moirasia main-process module that owns which process hosts the suite. It detects the native runtime, constructs the AppPresence and the authenticated `NativeHostClient` for it, and bootstraps native ownership with fail-fast semantics: a failed native bootstrap aborts the spawned host and quits rather than falling back. It owns the reconnect single-flight after disconnections, records host-initiated quits and exit-to-host, routes native UI events (`ui.openShell`, `ui.toggleShelf`, `host.uiStateChanged`) to the shell, and coordinates quit: the host is preserved for a recorded exit-to-host, otherwise `host.quitSuite` is requested and Electron teardown runs as its final callback. The composition root acquires it once at startup, starts it after the shell wiring exists, and passes its native client to the Feature runtime, the Shell window lifecycle, and Controller IPC. AppPresence keeps presence and menu-host spawning policy; `NativeHostClient` keeps the socket protocol.
- **Feature host** — the native `MoirasiaFeatureService` process that owns persistent Bonded, Shout, and Amove state in native mode. Its `FeatureRuntime` retains desired shell visibility, focus, and shelf visibility in-process and applies the relevant facts to Amove and Bonded on UI-state updates and startup. Parent and child use separate in-memory `HostUiState` values from `MoirasiaProtocol`; that type owns defaults, atomic patch validation, and full serialization, while `FeatureRuntime` owns consumer routing and module payloads. The parent `MoirasiaHost` keeps the latest valid reported values across supervised child restarts and replays them after the new generation's first full snapshot. Product modules keep their own applied policy state. The Feature host also serializes module snapshot and semantic-event publication and owns its native event revision. In local mode, the Electron main process remains the feature host.
- **Host UI-state recovery** — `native/moirasia-runtime/Sources/MoirasiaHost/HostUiStateRecovery.swift`; the MoirasiaHost module that owns the parent-side recovery copy of reported host UI state (shell visibility, main-window focus, Amove shelf visibility) and the child-generation replay cycle: generation fencing, the first-full-snapshot replay gate, coalescing of changes that land while a replay is in flight, and the restored `host.uiStateChanged` announcement. It stores its own `MoirasiaProtocol.HostUiState` value, which shares defaults, atomic patch validation, and full serialization with the separate child value. MoirasiaHost feeds it supervisor events, generation observations, and UI-state patches, and owns replay transport and the announcement broadcast. The copy stays memory-only.
- **Embedded feature** — a product running inside the suite window against the `MoirasiaFeature` contract (`register`/`dispose`/`activate`/`setActive`). Currently Amove, Bonded, and Shout.
- **Standalone application** — an independently packaged app under `apps/standalone`. Exithibition and Orbis are standalone-only and are not controlled by Moirasia.
- **Standalone launcher** — `runStandaloneLaunch` in `@moirasia/desktop-shell/main`; owns the single-instance lock, ready-time registration, activation re-focus, quit policy, and awaited teardown. Controlled apps enable its optional Moirasia login-item command branch; standalone-only apps disable it.
- **Standalone surface** — `acquireStandaloneSurface` in `@moirasia/desktop-shell/standalone-surface`; owns a standalone app's guarded primary window, app-local appearance registry, renderer loading, activation, and teardown without depending on feature catalogs or suite mode.
- **Host mode** — `suite` or `standalone`; the mode discriminates window ownership and the resource set an embedded feature requires.
- **Feature catalog** — pure-data owner of the shared facts about the three embedded features: Amove, Bonded, and Shout.
- **Application catalog** — the same for the three integrated applications the controller launches: Amove, Bonded, and Shout; `packages/desktop-shell/src/application-catalog.ts`.
- **Feature mode** — native mode or local mode; the two executions of the Feature runtime. A `NativeFeatureMode` adapter owns the authenticated native client, snapshot and health ingestion, and host-mediated install; a `LocalFeatureMode` adapter owns installed-truth in the Shell settings store and local loaders. Selected exactly once at Feature runtime construction; the adapters own every mode-varying behavior behind the runtime's unchanged interface.
- **Feature runtime** — `src/main/features/runtime.ts`; selects one **Feature mode** adapter at construction and owns the shared machinery: loaded instances, the per-feature serialization queue, load errors, and active-feature tracking. It presents one mode-agnostic interface; mode facts are never re-derived per method. It never loads a local controller after native mode is selected — the selection is structural, not a branch.
- **FeatureContext** — the discriminated context (`mode`, resource path maps, embedded `surface`) a feature receives at `register` time.
- **Feature surface host.** `packages/desktop-shell/src/feature-surface-host.ts` exports `acquireFeatureSurface` through `@moirasia/desktop-shell/feature-surface-host`. It returns a stable, replaceable renderer target in suite mode without controlling the shell window. In standalone mode it creates the primary window from catalog facts, installs guards and appearance handling, loads the renderer in `ready()`, and owns activation and teardown. The local path keeps product controllers and leases in Electron. The native path uses authenticated adapters while the feature service owns persistent state and leases.
- **Embedded feature lifecycle** — `packages/desktop-shell/src/feature-lifecycle.ts`; owns single-flight registration, Feature surface readiness, activation, reverse-order rollback, and exhaustive disposal for the repeated Bonded and Shout local/native adapters. Product adapters retain controllers, Runtime leases, updater facts, native decoding, commands, and validation. Amove retains its custom local and native lifecycle because its shelf and two-renderer behavior do not yet share this seam.
- **Shell window lifecycle** — `src/main/shell-window.ts`; owns replaceable primary-window generations. Menu Bar close detaches and destroys the shell renderer without disposing the selected feature owner. In native mode the service remains behind the host; in local mode Electron keeps the local controllers alive.
- **Amove shelf** — a separate Amove-owned `BrowserWindow`. A visible shelf survives shell renderer suspension; a hidden shelf renderer is destroyed and recreated by the next shelf action.
- **Runtime lease** — the cross-host exclusive lock ensuring one host owns a feature's sensitive session at a time. It stores an owner record, probes PID liveness, recovers stale ownership through a recovery marker, and releases by token. The deep implementation is `@moirasia/desktop-shell/runtime-lease`; each app keeps a thin adapter naming its lock and host.
- **Artifact fact** — the shared artifact facet in `packages/desktop-shell/src/feature-artifact-data.json`: filename (or napi base name), app-repo build output, suite staging destination, suite and standalone packaged destinations, and suite development source preference. `feature-catalog.ts` validates and freezes those facts.
- **Feature resource resolver** — `@moirasia/desktop-shell/feature-resources`; turns a feature id plus an explicit suite or standalone source root into native, worker, and asset paths without checking the filesystem. Suite and standalone contexts are adapters over it; `artifactPath` remains only the low-level filename formatter.
- **Feature staging adapter** — `scripts/feature-staging-plan.mjs` builds the deterministic copy records, while `scripts/stage-feature-binaries.mjs` runs the existing native commands and copies only the catalog-described feature artifacts into the clean staged tree.
- **Staged resources** — build outputs placed under `native/staged/…` so both suite development and suite packaging find them at the same repo-relative paths; packaged copies live under `Contents/Resources/features/<id>/…`.
- **Shared UI foundation.** `packages/design-system` owns common presentation semantics and generates React, plain-CSS and SwiftUI adapters. Platform mappings preserve native text/accessibility and mobile touch minimums. Product visualization tokens cannot redefine ordinary window chrome or controls.
- **Product bar / appearance.** `packages/desktop-shell` owns the 36px neutral bar, sun/moon control and per-product appearance persistence in `AppearanceRegistry`. The shared foundation owns token values; desktop-shell owns chrome layout and behavior.
- **App updater** — `@moirasia/desktop-shell` `AppUpdater`; owns GitHub Release checks for the General Updates card. It is not part of the Controller snapshot. A newer release is offered as a link that opens the GitHub release page in the system browser. In-place replacement remains out of scope while releases are unsigned. Nested standalone apps reuse the same module against their own GitHub repos.
