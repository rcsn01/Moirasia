# Standalone application architecture

Moirasia is a controller plus a feature host. As a controller, its main process talks to a small AppKit agent that discovers, opens, focuses, and gracefully quits the standalone Amove, Vox, Exithibition, Bonded, and Orbis bundles. As a host, it can run a product inside the suite process when the product ships a feature package.

Feature code lives in each product's own repository under `apps/integrated/` (Amove, Vox, Exithibition, Bonded, and Orbis) and implements the `MoirasiaFeature` contract from `@moirasia/desktop-shell/feature`: `register(ctx)` brings the product runtime up, `dispose()` tears it down completely, and `activate()` selects/focuses its primary surface. The host owns the discriminated `FeatureContext`, named resource maps, and the `EmbeddedFeatureSurface` supplied by `EmbeddedFeatureHost`. In suite mode the product has a reusable primary panel and authorizes IPC against the shell `webContents`; only standalone mode receives a feature-owned primary `BrowserWindow`. Utility windows such as Amove's Shelf remain feature-owned in either host.

Feature backends register at suite startup, while primary panel JavaScript is lazy in the shell renderer. `FeatureRuntime` (`src/main/features/runtime.ts`) resolves each installed backend through a string-literal `import()`, so rollup code-splits the backend and an uninstalled feature's code is never evaluated. React panel chunks load on first tab visit and stay mounted while the feature remains installed. Availability is a persisted boolean per product in the v3 shell settings, layered above the product's own settings so uninstalling loses nothing. Uninstall mid-session clears the active tab before `dispose()`; the code chunk stays in memory until relaunch, which the hub reports with a restart banner. Install mid-session registers the feature right away.

The shell sidebar groups General and Features under Essentials. The Features page manages every supported embedded product, including disabled or failed-to-load products. The Apps group links only installed backends that loaded successfully, so it never selects an unusable panel. Standalone bundles remain available through the macOS Applications menu and its keyboard shortcuts rather than through a renderer page.

Every feature must keep building as its own standalone app. The standalone entries (`apps/integrated/Amove/src/main/index.ts`, `apps/integrated/Vox/src/main/index.ts`, `apps/integrated/Exithibition/src/main/index.ts`, `apps/integrated/Bonded/src/main/index.ts`, and `apps/integrated/Orbis/src/main/index.ts`) stay thin and keep only identity and platform scoping: `app.setName`, the bundle id, the single-instance lock, login-item control, host-specific menus, and quitting when all windows close. Product behavior lives in each app repository's `src/`, consumed by both hosts as TypeScript source. Suite mode leaves app presence to Moirasia: features do not install menus, Dock icons, trays, or process-level quit policy.

The shared desktop shell supplies consistent primary-window chrome and appearance for Moirasia, Amove, Vox, Exithibition, Bonded, and Orbis. `DesktopAppShell` owns the full primary `BrowserWindow` viewport and is the only owner of the neutral 36px product bar and its compact sun/moon appearance toggle. The product bar never scrolls with app content. `DesktopNavigation` supports flat and labeled-group layouts and changes from a 220px sidebar to a horizontal row below 720px. `DesktopPage`, `ScrollArea`, and app-level containers decide how their content scrolls. `DesktopContentHeader` remains ordinary app content below the draggable product bar, so the shell does not pin it while its page scrolls. Embedded panels render content only, leaving the outer Moirasia shell as the sole owner of the product bar and appearance control in suite mode. Window dimensions remain controller-owned. Utility surfaces are intentionally excluded: Amove's shelf retains its compact borderless window and Vox's dictation overlay remains transparent, floating, and non-activating.

Login-item changes are executed by the target bundle through the versioned `--moirasia-control` protocol because macOS login services are scoped to the calling bundle. The command uses isolated Chromium data and exits after one JSON response.

Vox is the fifth embedded feature. Standalone and suite runtimes contend for a per-user lease at `Application Support/Moirasia/vox-runtime`; the loser starts no windows, IPC, database, or VoxNative process. A failed new suite installation rolls its preference back, while a startup conflict preserves the saved preference and exposes Retry. Suite mode uses the shell panel and a Vox-owned transparent overlay. Standalone mode keeps its dashboard, tray, Dock behavior, login-item control, bundle identity, and Command+2 launch path.

Standalone Vox keeps `Application Support/Vox/vox.sqlite`. A pristine suite store imports that database once into `Application Support/Moirasia/features/vox/vox.sqlite`, forces its copied login-item setting off, and then diverges. The import reads the source without modifying its database or WAL files. Both hosts intentionally share downloaded models in `Application Support/Vox/Models` and provider credentials in the `com.moirasia.vox.providers` Keychain service. Deleting suite data leaves standalone data and those shared resources intact. Each host owns its own macOS permission grants. Packaged native resources live at `Resources/native` for Vox and `Resources/features/vox/native` for Moirasia.

Bonded is the fourth embedded feature. Its controller receives its data directory and firewall-helper path from the host. Standalone settings stay under Bonded's `userData`; suite settings live under Moirasia's `features/bonded` directory. A pristine suite store imports the first valid standalone primary or backup document once, without changing the source. The two stores then diverge. A per-user runtime lease under `Application Support/Moirasia` prevents standalone Bonded and the embedded feature from controlling the global monitor and PF session together. The suite packages its helper at `Resources/features/bonded/native/BondedFirewallHelper`; standalone Bonded uses `Resources/native/BondedFirewallHelper`. Both require administrator approval when the helper is installed.

Orbis is the fifth controlled standalone application and another embedded feature. `apps/integrated/Orbis/src` owns its scanner, worker protocol, temporary `node:sqlite` index, context-isolated preload bridge, and SVG renderer. `apps/integrated/Orbis/src/main/index.ts` keeps only the standalone identity, menus, CSP, login-item control, and quit policy. The app builds one ESM worker at `scan-worker.mjs` via `scripts/build-worker.mjs`; Moirasia stages it at `native/staged/features/orbis/worker`, while standalone development stages it at `apps/integrated/Orbis/worker-dist`. Packaged builds place it at `Resources/features/orbis/worker/scan-worker.mjs`. `ORBIS_SCAN_ROOT` supplies a fixture root for automated scans, so tests never need to traverse the real startup volume. Full Disk Access belongs to Moirasia in suite mode and to the Orbis bundle in standalone mode.
