# Standalone application architecture

Moirasia is a controller plus a feature host. As a controller, its main process talks to a small AppKit agent that discovers, opens, focuses, and gracefully quits the standalone Amove, Vox, Exithibition, and Bonded bundles. As a host, it can run a product inside the suite process when the product ships a feature package.

A feature package (today only `@moirasia/feature-exithibition`, under `packages/`) implements the `MoirasiaFeature` contract from `@moirasia/desktop-shell/feature`: `register(ctx)` brings the product up, `dispose()` tears it down completely, and `activate()` raises its window. The host owns the `FeatureContext`: preload path, renderer URL or file, and the native helper executable path. A feature keeps its own `BrowserWindow` and registers its own IPC handlers, which must authorize the sender against the feature window's `webContents` because the suite process hosts several windows.

The suite loads features lazily. `FeatureRuntime` (`src/main/features/runtime.ts`) resolves each installed feature through a string-literal `import()`, so rollup code-splits the feature into its own chunk and an uninstalled feature's code is never evaluated. Availability is a persisted boolean per product in the v3 shell settings, layered above the product's own settings so uninstalling loses nothing. Uninstall mid-session runs `dispose()` immediately; the code chunk stays in memory until relaunch, which the hub reports with a restart banner. Install mid-session registers the feature right away.

Every feature must keep building as its own standalone app. The standalone entry (for Exithibition, `apps/Exithibition/src/main/index.ts`) stays thin and keeps only identity and platform scoping: `app.setName`, the bundle id, the single-instance lock, login-item control, and quitting when all windows close. Product behavior lives in the feature package, consumed by both hosts as TypeScript source.

The shared desktop shell supplies consistent primary-window chrome and appearance for Moirasia, Amove, Vox, Exithibition, and Bonded. `DesktopAppShell` owns the neutral 36px title bar with a compact sun/moon appearance toggle; `DesktopNavigation` changes from a 220px sidebar to a horizontal row below 720px; `DesktopPage` preserves app-selected content widths and scrolling; and `DesktopContentHeader` holds product operations below the draggable chrome. Window dimensions remain controller-owned. Utility surfaces are intentionally excluded: Amove's shelf retains its compact borderless window and Vox's dictation overlay remains transparent, floating, and non-activating.

Login-item changes are executed by the target bundle through the versioned `--moirasia-control` protocol because macOS login services are scoped to the calling bundle. The command uses isolated Chromium data and exits after one JSON response.
