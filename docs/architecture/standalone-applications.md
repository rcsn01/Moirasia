# Standalone application architecture

Moirasia is a controller plus a feature host. As a controller, its main process talks to a small AppKit agent that discovers, opens, focuses, and gracefully quits the standalone Amove, Vox, Exithibition, Bonded, and Orbis bundles. As a host, it can run a product inside the suite process when the product ships a feature package.

Feature code lives in each product's own repository under `apps/integrated/` (Amove, Exithibition, and Orbis) and implements the `MoirasiaFeature` contract from `@moirasia/desktop-shell/feature`: `register(ctx)` brings the product runtime up, `dispose()` tears it down completely, and `activate()` selects/focuses its primary surface. The host owns the discriminated `FeatureContext`, named resource maps, and the `EmbeddedFeatureSurface` supplied by `EmbeddedFeatureHost`. In suite mode the product has a reusable primary panel and authorizes IPC against the shell `webContents`; only standalone mode receives a feature-owned primary `BrowserWindow`. Utility windows such as Amove's Shelf remain feature-owned in either host.

Feature backends register at suite startup, while primary panel JavaScript is lazy in the shell renderer. `FeatureRuntime` (`src/main/features/runtime.ts`) resolves each installed backend through a string-literal `import()`, so rollup code-splits the backend and an uninstalled feature's code is never evaluated. React panel chunks load on first tab visit and stay mounted while the feature remains installed. Availability is a persisted boolean per product in the v3 shell settings, layered above the product's own settings so uninstalling loses nothing. Uninstall mid-session clears the active tab before `dispose()`; the code chunk stays in memory until relaunch, which the hub reports with a restart banner. Install mid-session registers the feature right away.

The shell sidebar groups General and Features under Essentials. The Features page manages every supported embedded product, including disabled or failed-to-load products. The Apps group links only installed backends that loaded successfully, so it never selects an unusable panel. Standalone bundles remain available through the macOS Applications menu and its keyboard shortcuts rather than through a renderer page.

Every feature must keep building as its own standalone app. The standalone entries (`apps/integrated/Amove/src/main/index.ts`, `apps/integrated/Exithibition/src/main/index.ts`, and `apps/integrated/Orbis/src/main/index.ts`) stay thin and keep only identity and platform scoping: `app.setName`, the bundle id, the single-instance lock, login-item control, host-specific menus, and quitting when all windows close. Product behavior lives in each app repository's `src/`, consumed by both hosts as TypeScript source. Suite mode leaves app presence to Moirasia: features do not install menus, Dock icons, trays, or process-level quit policy.

The shared desktop shell supplies consistent primary-window chrome and appearance for Moirasia, Amove, Vox, Exithibition, Bonded, and Orbis. `DesktopAppShell` owns the neutral 36px title bar with a compact sun/moon appearance toggle; `DesktopNavigation` supports flat and labeled-group layouts and changes from a 220px sidebar to a horizontal row below 720px; `DesktopPage` preserves app-selected content widths and scrolling; and `DesktopContentHeader` holds product operations below the draggable chrome. Embedded panels render content only, so the outer Moirasia shell remains the sole owner of the title bar and appearance control in suite mode. Window dimensions remain controller-owned. Utility surfaces are intentionally excluded: Amove's shelf retains its compact borderless window and Vox's dictation overlay remains transparent, floating, and non-activating.

Login-item changes are executed by the target bundle through the versioned `--moirasia-control` protocol because macOS login services are scoped to the calling bundle. The command uses isolated Chromium data and exits after one JSON response.

Orbis is the fifth controlled standalone application and the third embedded feature. `apps/integrated/Orbis/src` owns its scanner, worker protocol, temporary `node:sqlite` index, context-isolated preload bridge, and SVG renderer. `apps/integrated/Orbis/src/main/index.ts` keeps only the standalone identity, menus, CSP, login-item control, and quit policy. The app builds one ESM worker at `scan-worker.mjs` via `scripts/build-worker.mjs`; Moirasia stages it at `native/staged/features/orbis/worker`, while standalone development stages it at `apps/integrated/Orbis/worker-dist`. Packaged builds place it at `Resources/features/orbis/worker/scan-worker.mjs`. `ORBIS_SCAN_ROOT` supplies a fixture root for automated scans, so tests never need to traverse the real startup volume. Full Disk Access belongs to Moirasia in suite mode and to the Orbis bundle in standalone mode.
